# AutoMCM draw-image

为论文生成非数值流程图、架构图和概念示意图。数值结果、拟合曲线、散点图、热力图和统计图必须由 Python 代码生成，不得使用生成式图像替代。

## 路径选择

按以下规则选择，仓库脚本是标准自动化路径：

1. 设置了 `OPENAI_API_KEY` 时，运行原项目的 `scripts/draw_image.py`，由脚本直接调用 OpenAI Images API。
2. 未设置 API Key、但当前 Codex 运行时**实际暴露了**图像生成工具时，可直接调用该工具；不得仅凭安装了 `codex` CLI 推断该能力存在。
3. 两条路径均不可用时，不得静默跳过：优先留下可复现的 Python/MATLAB 绘图代码；暂时无法代码化时，在目标 LaTeX 图位留下带需求说明的注释和 `\missingfigure{描述}`。

预检脚本路径：

```bash
python scripts/draw_image.py --check
```

输出语义：

- `method=api_key available=True`：可运行 API 脚本。
- `method=none available=False` 且退出码为 2：脚本路径不可用；在目标图位生成 Python/MATLAB 代码或 LaTeX 注释回退。

## 决策树

```text
需要插图？
├─ 图中数值来自数据或模型输出
│  └─ 用 matplotlib / seaborn / 可复现代码生成
└─ 非数值流程、架构或概念示意
   ├─ 极简几何图（不超过 3 个框）→ TikZ
   ├─ OPENAI_API_KEY 可用 → scripts/draw_image.py（标准自动化路径）
   ├─ 当前运行时实际暴露图像工具 → 原生生成
   └─ 均不可用 → Python/MATLAB 绘图代码；无法代码化时留 LaTeX 注释和 \missingfigure{}
```

## 模型调用边界

- Codex 编排模型由 Codex 配置或启动脚本的 `--model` / `AUTOMCM_CODEX_MODEL` 决定。
- Images API 模型由 `draw_image.py --model` / `AUTOMCM_IMAGE_MODEL` 决定，默认 `gpt-image-2`。
- 不得把 `gpt-image-2` 传给 `codex exec --model`，也不得把 GPT 编排模型传给 `draw_image.py --model`。
- `gpt-image-1.5`、`gpt-image-1`、`gpt-image-1-mini` 仅保留兼容性；新任务使用 `gpt-image-2`。

## 原生 Codex 生成要求

调用当前环境的图像生成能力时：

- 明确要求白色背景、论文风格、清晰箭头和简洁配色。
- 明确指定中文或英文标签，避免大量正文。
- 生成后检查文字、方向、节点遗漏和逻辑关系。
- 将最终资产保存到 `CUMCM_Workspace/latex/images/`，再写入 `\includegraphics`。
- 若工具只返回会话图片而没有本地文件，先完成受支持的导出/保存；文件未落盘前不得假定 LaTeX 可引用。

## OpenAI Images API 脚本

密钥只能通过环境变量提供：

```bash
python scripts/draw_image.py \
  --prompt "Clean technical flowchart on white background: 读取赛题 → 建模 → 验证 → LaTeX → PDF. Chinese labels, blue-gray palette, clear arrows." \
  --output "CUMCM_Workspace/latex/images/fig00_pipeline.png" \
  --size 1024x1536 \
  --quality high
```

禁止把 `OPENAI_API_KEY` 写入代码、命令历史示例、日志、`thought_process.md` 或 Git 跟踪文件。不得读取 `~/.codex/auth.json`、`CODEX_AUTH_TOKEN` 或其他本地认证材料。

如需覆盖生图模型，只使用图像专用参数或环境变量：

```bash
AUTOMCM_IMAGE_MODEL=gpt-image-2 python scripts/draw_image.py \
  --prompt "Academic architecture diagram on white background" \
  --output "CUMCM_Workspace/latex/images/fig_architecture.png"
```

## 无 API Key 回退（强制）

每次准备生成图片时先运行：

```bash
python scripts/draw_image.py --check
```

若退出码为 2，必须在**同一个预定图位**留下可执行来源或明确注释，不得只在日志里说“跳过”。推荐直接再次调用原命令并指定回退类型：

```bash
# 默认：在 CUMCM_Workspace/src/figures/ 生成 Python 脚手架
python scripts/draw_image.py \
  --prompt "建模流程图：读取题目 → 建模 → 验证 → LaTeX" \
  --output "CUMCM_Workspace/latex/images/fig00_pipeline.png" \
  --fallback python

# MATLAB 项目
python scripts/draw_image.py ... --fallback matlab

# 确实无法代码化时，生成可插入论文的 LaTeX 注释片段
python scripts/draw_image.py ... --fallback comment
```

生成的 Python/MATLAB 文件是待补全脚手架。Agent 必须：

1. 按提示词补全实际结构、节点、连线、标签和配色，不能把自动生成的 `TODO` 占位图当成最终图。
2. 运行代码并确认目标图片真实存在，之后才能写入 `\includegraphics`。
3. 对数据图、拟合曲线、热力图和模型输出，始终直接编写并运行 Python/MATLAB，不等待 Images API。
4. 如果只能留注释，把生成的 `.tex` 内容放到论文原本应出现图片的位置，并注明目标文件名和图片需求。

## 提示词模板

流程图：

```text
Clean technical flowchart on a white background with [Chinese/English] labels.
Steps: (1) ... → (2) ... → (3) ...
Decision: [condition] → Yes: ... / No: ...
Style: academic, minimal, blue-gray palette, sans-serif, clear arrows.
```

架构图：

```text
System architecture diagram on a white background.
Components: [component and responsibility list].
Connections: [data/control flow].
Style: academic, clean labeled boxes, no decorative elements.
```

## LaTeX 集成

只有文件实际存在后才能加入论文：

```latex
\begin{figure}[htbp]
  \centering
  \includegraphics[width=0.85\textwidth]{images/fig00_pipeline.png}
  \caption{建模流程图}
  \label{fig:pipeline}
\end{figure}
```

生成后核验：

- 文件存在且可打开。
- 图中标签无乱码或事实错误。
- 图注与正文引用一致。
- 图片不伪装成真实数据或模型结果。
